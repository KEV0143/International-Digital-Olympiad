## Установка и запуск

Для полного тестирования потребуются Python версии 3.12 или выше, установленные Google Chrome, Firefox и доступ к Интернету. <br>
Для запуска из корневого каталога проекта выполните команду:

```powershell
python app.py --browser both
```
( Также можно запустить исполнение .py нажав на Python File app.py )

Команда выполняет 110 проверок: по 55 в каждом браузере, затем формирует общий отчёт Allure.
В терминале выводятся число пройденных проверок, время выполнения и путь к отчёту.

При первом запуске `app.py` создаёт виртуальное окружение `tools/.venv/` и устанавливает зависимости Python и Allure. 

<img width="1116" height="654" alt="1" src="https://github.com/user-attachments/assets/d488c6d3-652f-4f09-a51b-719645f0a98f" />

Для формирования HTML-отчёта используется
Node.js с npm; при отсутствии подходящей версии локальная копия устанавливается
в `tools/.runtime/`. Драйверы для установленных браузеров подбирает Selenium Manager.

Повторные запуски используют подготовленное окружение. При временных ошибках установки
Allure предусмотрено до трёх попыток и резервная загрузка недостающих пакетов.
Журналы подготовки создаются в `data/results/setup/`.

<img width="1113" height="657" alt="2" src="https://github.com/user-attachments/assets/6e9aeacc-a418-4908-bd23-06822b5359d4" />


| Команда | Режим выполнения |
|---|---|
| `python app.py` | Chrome, 55 проверок, формирование HTML-отчёта. |
| `python app.py --browser firefox` | Firefox, 55 проверок, формирование HTML-отчёта. |
| `python app.py --workers 8` | Восемь исполнителей в Chrome. |
| `python app.py --headed` | Отображение окна браузера. |
| `python app.py -m "calendars and negative"` | Пять негативных проверок Calendars. |
| `python app.py --browser both --sequential` | Последовательное выполнение в двух браузерах. |
| `python app.py --no-report --no-pause` | Выполнение без формирования HTML и ожидания Enter; данные Allure сохраняются. |
| `python app.py --help` | Справка по параметрам командной строки. |

Исполнитель (worker) – процесс Pytest, выполняющий одну проверку за раз.
Параметр `--workers` принимает значения от 1 до 12; по умолчанию используется
4 исполнителя на браузер. При `--browser both` одновременно работают до 8 исполнителей.
Параметр `--sequential` запускает браузеры по очереди. Параметр `--ui-timeout`
задаёт предел ожидания элемента в секундах; значение по умолчанию – 15.

<img width="1000" height="542" alt="3" src="https://github.com/user-attachments/assets/32c97e97-797e-47dc-ab6d-cc938f84affa" />


Ctrl+C останавливает текущий запуск. В интерактивном режиме после вывода статистики,
затраченного времени и пути к отчёту программа ожидает Enter.
Для запуска из скриптов предусмотрен `--no-pause`. Код завершения 0 означает успешный
прогон; ненулевой код сообщает об ошибке или прерывании.

Настройки IDE: интерпретатор `tools/.venv/Scripts/python.exe`, рабочий каталог – корень проекта.
После подготовки окружения доступен прямой запуск Pytest:

```powershell
.\tools\.venv\Scripts\python.exe -m pytest -c data/config/pytest.ini --rootdir=. --browser chrome -n 4 --dist worksteal
```

<img width="1406" height="528" alt="4" src="https://github.com/user-attachments/assets/53ff712d-2575-4be5-91ef-1fabbda4aabf" /><br>


В этом режиме Allure JSON сохраняется в `data/results/direct/allure-results/`.
При прямом запуске Pytest параметры `-c` и `--rootdir` указываются явно.
При запуске через `app.py` они передаются автоматически.

## Результаты выполнения

Результаты создаются при выполнении тестов в каталоге `data/results/run-<UTC>-<id>/`.
Его путь выводится в терминал и записывается в `data/results/last-run.txt`.
Пути в таблице указаны относительно каталога запуска.

| Файл или каталог | Назначение |
|---|---|
| `allure-report/index.html` | HTML-отчёт Allure; формируется по умолчанию, если не указан `--no-report`. |
| `allure-results/` | Объединённые данные Allure для формирования HTML-отчёта. |
| `chrome/`, `firefox/` | Allure JSON, JUnit XML, журнал Pytest, каталог проверок и длительности фаз. |
| `run.json` | Параметры запуска, результаты по браузерам и время выполнения. |
| `report.log` | Журнал формирования HTML-отчёта; создаётся при включённом формировании HTML. |
| `verification.json` | Результат сверки отчётных данных; создаётся командой `verify`. |

Для просмотра результатов откройте `allure-report/index.html` в браузере.
Отчёт содержит статусы, длительности, шаги и ожидаемые результаты проверок.
Для неуспешных проверок прикрепляются диагностические вложения.

## Архитектура проекта

```text
app.py                    точка входа и обработка параметров запуска
utils/
  pages/                  Page Objects и базовые операции браузера
  components/             компоненты Popup и JetpackForm
  browser/                создание WebDriver и тайм-ауты команд
  reporting/              Allure, вложения и вывод в терминал
  pytest_plugin.py        фикстуры, регистрация проверок и длительности фаз
  validation.py           проверка параметров и режима Python
tests/
  ui/                     проверки интерфейса
  framework/              тесты инфраструктуры
tools/
  environment/            подготовка окружения и зависимостей
  runner/                 управление процессами Pytest и сборка Allure
  verification/           проверка отчётных данных
  documentation/          формирование каталога сценариев
  reporting/              зависимости Allure для npm
  ci/                     объединение результатов матрицы браузеров
data/
  config/                 конфигурация Pytest, Ruff и Allure
  dependencies/           фиксированные версии зависимостей
.github/workflows/        конфигурация GitHub Actions
```

Для каждого теста создаётся новая сессия WebDriver. Фикстура `driver` имеет область
действия `function`. Локаторы и операции браузера находятся в Page Objects
и компонентах `utils`. Для ожиданий используется `WebDriverWait` с интервалом опроса
0,1 с; неявное ожидание отключено.

ID, названия, действия и ожидаемые результаты задаются декораторами `scenario`
и `scenario_cases`. Эти данные используются в Allure.
Окружение, установленные пакеты, кеш и каталог `data/results/` создаются при запуске.

В ADS-P01 задержка появления рекламы отсчитывается от `DOMContentLoaded`.
Наблюдатель изменений DOM устанавливается до выполнения скриптов страницы
и регистрирует активации рекламного окна, включая кратковременные открытия.

- Объём: 55 проверок в Chrome без отображения окна (headless). Размер окна: 1440 x 1100.

- Измеряемый интервал: от запуска до завершения процесса Pytest. Зависимости установлены заранее;

- Целевой шаг измерений: 1 с. CPU относится ко всей системе; память и число процессов
  относятся к дереву Pytest, включая исполнителей, драйверы и браузеры.

## Проверка результатов

Тесты интерфейса и инфраструктуры запускаются отдельно. Команда `check` выполняет
176 тестов инфраструктуры: проверяет подготовку окружения, обработку ошибок,
сбор отчётов и работу вспомогательных компонентов.

| Команда | Назначение |
|---|---|
| `python app.py check` | Статический анализ Ruff, проверка форматирования, сверка каталога сценариев и тесты инфраструктуры. |
| `python app.py verify --browser chrome` | Сверка полного прогона Chrome с каталогом, Allure, JUnit и длительностями фаз. |
| `python app.py verify --browser both` | Сверка полного прогона с каталогом, Allure, JUnit и длительностями фаз. |

Команда `verify` работает с результатами последнего запуска и требует полного
выполнения без фильтра `-m`.
Указанный набор браузеров должен соответствовать выполненному тестированию.
Для выбора другого каталога результатов используется параметр `--folder`.
Если сформирован HTML-отчёт, проверяются его наличие и итоговая статистика.
